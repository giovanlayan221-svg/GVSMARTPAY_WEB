GVSMARTPAY — paket siap deploy ke Vercel
==========================================

ISI FOLDER INI (jangan diubah strukturnya, upload/deploy folder ini apa adanya):

  index.html                 -> website utama (nama file HARUS index.html
                                 supaya otomatis jadi halaman utama di Vercel)
  firebase-messaging-sw.js   -> wajib untuk notifikasi push
  package.json               -> daftar dependensi untuk api/notify.js
  api/reward.js              -> BARU: saldo otomatis (Balapan Transaksi, Referral,
                                 Voucher, pencairan GVCLIPPER). Pakai variabel
                                 FIREBASE_SERVICE_ACCOUNT yang sama dengan notify.js
  vercel.json                -> BARU: cron harian tutup balapan + header PWA
  manifest.webmanifest, sw.js, icon-*.png, apple-touch-icon.png
                             -> BARU: file PWA asli (perbaikan "info aplikasi hitam")
  api/notify.js              -> pengirim notifikasi (pengganti Cloud Function,
                                 tidak butuh paket Blaze)
  firestore.rules.txt        -> BUKAN untuk di-deploy, cuma referensi.
                                 Isinya harus ditempel manual ke:
                                 Firebase Console > Firestore Database > Rules > Publish

CARA DEPLOY (pilih salah satu):
1) Lewat Vercel CLI:
   - install Vercel CLI (npm i -g vercel), lalu di folder ini jalankan: vercel --prod
2) Lewat Vercel Dashboard:
   - Kalau project sudah ada: buka repo/foldernya, timpa semua file dengan isi
     folder ini, lalu redeploy.
   - Kalau bikin baru: New Project > Upload folder ini > Deploy.

SETELAH DEPLOY:
1. Buka Firebase Console > Firestore Database > Rules, tempel isi
   firestore.rules.txt, lalu Publish. (Lewati kalau rules-mu sudah versi ini.)
2. FIREBASE_CONFIG di dalam index.html sudah terisi project Firebase-mu
   (gvsmartpay). Kalau kamu pindah ke project Firebase lain, ganti nilainya
   di bagian atas <script> pada index.html.
3. Untuk notifikasi benar-benar masuk ke notifikasi HP (bukan cuma di dalam
   web):
   a. Firebase Console > Project settings (ikon gerigi) > Service accounts
      > "Generate new private key" -> download file JSON-nya. (Gratis, TIDAK
      butuh paket Blaze.)
   b. Buka file JSON itu, copy SEMUA isinya jadi satu baris.
   c. Di Vercel: Project > Settings > Environment Variables, tambah:
        Name  : FIREBASE_SERVICE_ACCOUNT
        Value : (tempel seluruh isi JSON tadi)
      lalu Save dan Redeploy.
4. Kalau di Firebase Console > Cloud Messaging belum ada "Web Push
   certificate", buat satu, lalu isi nilainya ke FCM_VAPID_KEY di bagian
   atas <script> pada index.html (cari baris "const FCM_VAPID_KEY=''").
   Tanpa ini, notifikasi hanya bekerja saat web sedang dibuka.

Pendaftar PERTAMA yang membuat akun di aplikasi ini otomatis jadi admin.

PENTING (UPDATE FITUR REWARD & PWA)
-----------------------------------
- Tempel ulang firestore.rules.txt ke Firebase Console > Rules > Publish
  (ada koleksi baru: raceEntries, bonuses, vouchers, referrals, clips, dll).
- Fitur reward butuh FIREBASE_SERVICE_ACCOUNT di Vercel (langkah 3 di atas).
  Tanpa itu, saldo bonus TIDAK akan masuk otomatis.
- Setelah deploy, HAPUS aplikasi lama dari layar utama HP, buka lagi lewat Chrome,
  lalu "Tambahkan ke layar utama / Instal aplikasi".

UPDATE: TUKAR POIN & NOTIFIKASI
-------------------------------
- Tempel ulang firestore.rules.txt (ada koleksi baru: rewards, rewardClaims, pointLogs).
- Poin: Rp1.000 = 10 poin, dari transaksi yang berstatus berhasil dan dari voucher.
- Admin Dashboard > Hadiah Poin: tambah hadiah (gambar 16:9, harga poin, stok, data yang diisi pelanggan),
  lalu proses penukaran (Selesai / Tolak, poin otomatis kembali kalau ditolak).
- api/reseller-callback.js: alamat webhook untuk reseller. Isi env RESELLER_WEBHOOK_SECRET di Vercel.


INTEGRASI HAYBI H2H (server-side)
---------------------------------
- api/_haybi.js : klien HAYBI (signature md5, ref_id otomatis, timeout 15 dtk). Hanya server.
- api/haybi.js  : endpoint internal /api/haybi (wajib login). Frontend TIDAK pernah memegang API key.
- Di Vercel > Project > Settings > Environment Variables, tambah (Production, Preview, Development):
    HAYBI_USERNAME = (username H2H dari HAYBI)
    HAYBI_API_KEY  = (API key dari HAYBI)
  lalu Redeploy. Jangan pakai awalan NEXT_PUBLIC_.
- Produk di Admin > Produk harus punya kolom SKU = kode produk HAYBI. Tanpa SKU, pesanan tetap
  diproses manual seperti sebelumnya.


INTEGRASI HAYBI H2H (BARU)
--------------------------
- api/_haybi.js : klien HAYBI (signature md5, ref_id otomatis, timeout 15 detik). Server-side saja.
- api/haybi.js  : satu-satunya pintu dari website ke HAYBI. Wajib login.
    admin saja  : saldo, produk, harga (tombol "HAYBI H2H" di Admin > Pesanan)
    pemilik/admin: kirim (otomatis setelah pesanan dibuat), status (tombol "Cek status HAYBI")
- Isi 2 Environment Variable di Vercel (Settings > Environment Variables), lalu REDEPLOY:
    HAYBI_USERNAME = username H2H dari HAYBI
    HAYBI_API_KEY  = API key dari HAYBI
- Pesanan baru HANYA dikirim ke HAYBI kalau produknya punya SKU (kode produk HAYBI) di
  Admin > Produk. Produk tanpa SKU tetap diproses manual seperti sebelumnya.
- Callback HAYBI belum dipasang (format callback belum ada di dokumentasi). Sementara pakai
  tombol "Cek status HAYBI" untuk pesanan yang masih pending.

- firestore.rules.txt DIPERBARUI: salin isinya ke Firebase Console > Firestore > Rules > Publish.


- FOTO PRODUK: Admin > Produk > Kelola Foto. Wajib publish firestore.rules.txt terbaru (ada koleksi 'icons').


STATUS OTOMATIS & NOTIFIKASI (BARU)
-----------------------------------
- Status pesanan HAYBI sekarang otomatis: server mengecek beberapa detik setelah pesanan dikirim, aplikasi yang terbuka
  mengecek tiap beberapa detik, dan ada alamat callback: https://DOMAIN-KAMU/api/haybi-callback
  (daftarkan di panel HAYBI kalau ada kolom Callback URL; isi payload tidak dipercaya, status selalu dicek ulang ke HAYBI).
- Notifikasi anti-spam: tag tetap per pesanan, token lama dibersihkan, maksimal 3 token terbaru per akun.


BARU: BEBAS NOMINAL E-WALLET
  1. Tempel ulang firestore.rules.txt ke Firebase Console > Firestore > Rules > Publish.
  2. Login admin > Admin > Produk > kartu "Bebas Nominal E-Wallet": isi SKU HAYBI + biaya admin
     untuk DANA, OVO, GoPay, ShopeePay, LinkAja, lalu Simpan. SKU kosong = tidak tampil.
  3. Pesanan bebas nominal otomatis dikirim ke HAYBI dengan parameter nominal_bebas (nominal saja, tanpa biaya admin).

=== CATATAN VERSI 13 (wajib dibaca) ===
1. Firebase Console > Firestore Database > Rules: salin isi firestore.rules.txt lalu tekan PUBLISH.
   Akun admin kebal aturan, jadi bug izin cuma terasa di akun pengguna biasa. Tanpa langkah ini
   akun pengguna bisa gagal upload foto profil, membuat kode referral, atau mendaftarkan notifikasi.
2. Vercel > Settings > Environment Variables: FIREBASE_SERVICE_ACCOUNT harus terisi (dipakai /api/notify, /api/reward, /api/pay).
   Setelah deploy, buka Pengaturan > Diagnosa akun (di akun pengguna biasa) dan tekan "Jalankan pemeriksaan".
3. Notifikasi: buka Pengaturan > Notifikasi, tekan "Aktifkan / perbarui" lalu "Kirim notifikasi tes" di tiap HP admin dan pengguna.
   Pasang aplikasi ke layar utama dan matikan pembatasan baterai untuk Chrome/GVSMARTPAY.
4. Tema gelap: Pengaturan > Tema tampilan.

PRODUK PER KATEGORI (hemat baca Firestore) - deploy-13
==========================================================================
Urutan setelah deploy:
 1. Buka web memakai akun ADMIN sekali. Indeks kategori dibuat otomatis (1x baca seluruh produk),
    disimpan di dokumen meta/ver (field pidx). Selama indeks belum ada, kategori dianggap tersedia

 2. Firebase Console > Firestore > Indexes > Composite > Add index:
      Collection ID : products
      Fields        : group (Ascending), price (Ascending)   | Query scope: Collection
    (isi sama ada di firestore.indexes.json). Tunggu status "Enabled". Sebelum itu aplikasi tetap jalan
    lewat mode cadangan: satu kategori diambil sekaligus (maks 300 dokumen), tetap tidak seluruh koleksi.
 3. Firestore > Rules: tempel firestore.rules.txt lalu Publish (aturan baru products membatasi query pelanggan
    maksimal limit 300). Lakukan SETELAH langkah 1 dan setelah versi baru ter-deploy.

NOTIFIKASI (Web Push / FCM) - deploy-14
==========================================================================
Arsitektur asli: FCM Web lewat firebase-admin di Vercel (api/_push.js, api/notify.js), token disimpan di users/{uid}.fcmTokens,
service worker firebase-messaging-sw.js (scope /firebase-cloud-messaging-push-scope) + sw.js (cache PWA, scope /).

AKSI WAJIB agar perbaikan utama berjalan:
 1. Vercel > Settings > Environment Variables: tambah  CRON_SECRET  (isi bebas, panjang & acak). Lalu Redeploy.
 2. Jadwalkan pemanggilan ke  https://<domainmu>/api/sync-pending  tiap 1-2 menit memakai layanan cron gratis
    (mis. cron-job.org) dengan header  Authorization: Bearer <CRON_SECRET>  (atau tambahkan ?secret=<CRON_SECRET> di URL).
    Ini yang membuat status pesanan dicek dari SERVER walau aplikasi pelanggan tertutup. Tanpa langkah ini, pesanan yang
    belum selesai dalam ~14 detik pertama baru berubah kalau callback HAYBI aktif atau ada aplikasi yang sedang terbuka.
 3. (Disarankan) Daftarkan alamat  https://<domainmu>/api/haybi-callback  di panel HAYBI bila fitur callback tersedia.
OPSIONAL:
 - Firestore > TTL policy: collection pushLogs, field expireAt (log pengiriman otomatis terhapus setelah 14 hari).
 - Tidak ada perubahan Firestore Rules untuk notifikasi (pushLogs hanya ditulis/dibaca server; admin melihatnya lewat
   Pengaturan > Notifikasi > "Lihat log pengiriman terakhir").

PUNYAKIOS (provider tambahan, HAYBI tetap jalan) - deploy-15
==========================================================================
Dibangun dari dokumentasi resmi https://punyakios.id/docs (Partner API v1.3.0, 26 Sep 2026). BELUM diuji ke server PunyaKios
sungguhan (tidak ada kredensial & tidak ada transaksi berbayar yang dijalankan). Uji dengan langkah di bawah sebelum dipakai pelanggan.

ENV di Vercel (Settings > Environment Variables), lalu Redeploy:
   PUNYAKIOS_API_KEY      = pk_live_...   (X-API-KEY)
   PUNYAKIOS_API_SECRET   = ps_live_...   (X-API-SECRET; juga kunci verifikasi webhook)
   PUNYAKIOS_BASE_URL     = (opsional) default https://punyakios.id/api/v1/partner  (harus https)
Kredensial hanya dibaca server; tidak ada yang dikirim ke browser, dan tidak dicatat di log.

WEBHOOK: minta Administrator PunyaKios mendaftarkan SATU URL:  https://<domainmu>/api/punyakios-callback
(PunyaKios memakai 1 URL untuk semua event.) Panel Admin > Pesanan > PunyaKios > Cek Saldo menampilkan URL webhook yang terdaftar
dan apakah sudah sesuai. Tanpa webhook, status tetap diperbarui oleh pengecekan status + penyapu /api/sync-pending (deploy-14).

PEMETAAN PRODUK (tidak ada produk yang diubah otomatis):
 1. Admin > Pesanan > PunyaKios > Katalog: lihat SKU & harga modal, tekan "Salin SKU".
 2. Admin > Produk: pada produk yang dimaksud isi kolom SKU, pilih "Provider: PunyaKios", isi Modal. Harga jual, status Aktif,
    kategori, dan foto tetap diatur seperti biasa. Produk tanpa pilihan provider tetap memakai HAYBI seperti sebelumnya.
 3. Game dengan ID + Zone tidak dikirim otomatis ke PunyaKios (format tujuan tidak ada di dokumentasi) -> diproses manual.
 4. Bebas nominal e-wallet tetap HAYBI (PunyaKios tidak punya fitur nominal bebas).

DATABASE: tidak ada migrasi dan tidak ada data yang diubah. Tambahan: field products.provider (opsional), dan koleksi baru
orderCosts (modal & untung per pesanan PunyaKios yang sukses; hanya ditulis/dibaca server, tidak ada perubahan Rules).
Field pesanan haybiRef/haybiState dipakai sebagai "referensi/status provider" untuk kedua provider; field provider membedakannya.

RENCANA UJI (perlu persetujuan kamu sebelum ada transaksi berbayar):
 a. Isi env, redeploy, buka Admin > Pesanan > PunyaKios > Cek Saldo. Harus muncul saldo & mode (LIVE/SANDBOX).
 b. Katalog: harus muncul daftar produk dengan harga modal.
 c. Kalau PunyaKios menyediakan akun/mode sandbox, uji order di sana dulu.
 d. Pilih 1 produk termurah (mis. pulsa Rp5.000), set Provider: PunyaKios + SKU, beli 1x dengan akun uji. Cek: pesanan berubah ke
    Berhasil, SN muncul, saldo pelanggan terpotong sekali, saldo PunyaKios berkurang sebesar modal, "Untung 30 hari" bertambah.
 e. Uji gagal: nomor tujuan salah pada produk murah -> pesanan harus Gagal & saldo kembali.

BAYAR PAKAI QRIS PUNYAKIOS DI CHECKOUT - deploy-16
==========================================================================
Di layar Konfirmasi Pembayaran ada tombol baru "Bayar dengan QRIS" (di samping "Bayar Sekarang" = saldo GVSMARTPAY, tidak diubah).
Berlaku untuk produk HAYBI maupun PunyaKios: QRIS hanya cara BAYAR dari pelanggan; provider pengirim produk tetap mengikuti kolom
Provider pada produk.

ALUR: pelanggan tekan Bayar dengan QRIS -> server membuat QRIS di PunyaKios (pesanan BELUM dibuat) -> pelanggan scan & bayar
-> webhook / cek status resmi PunyaKios ("paid") -> pesanan dibuat SEKALI -> dikirim ke provider -> notifikasi.
ATURAN (sesuai keputusan pemilik):
 - Biaya QRIS dibebankan ke pelanggan (ditampilkan sebelum bayar; angka dari PunyaKios, bukan hitungan sendiri).
 - Pesanan GAGAL setelah dibayar QRIS: saldo GVSMARTPAY pelanggan bertambah sebesar yang dibayar (harga + biaya QRIS).
 - Dibayar setelah batas 30 menit, atau harga produk berubah / produk nonaktif sebelum dibayar: tidak jadi pesanan, uang masuk
   saldo GVSMARTPAY pelanggan (pelanggan diberi notifikasi).
 - Dibayar kurang dari seharusnya: TIDAK diproses otomatis, admin dapat notifikasi "Pembayaran QRIS tidak sesuai" (cek manual).
 - Maksimal 3 QRIS belum dibayar per akun. QRIS yang tidak terdeteksi bayar >24 jam ditutup oleh penyapu.
DEPOSIT: karena QRIS dan produk dari dua penyedia, pastikan saldo deposit di PunyaKios DAN HAYBI cukup. Uang QRIS masuk ke
PunyaKios (dokumentasi tidak merinci apakah masuk ke saldo partner; konfirmasi ke PunyaKios). Produk HAYBI tetap dibayar dari
deposit HAYBI.
YANG PERLU DIPASTIKAN:
 1. Webhook PunyaKios yang sama (/api/punyakios-callback) harus menerima event pembayaran (payment_update). Minta Administrator
    PunyaKios mengaktifkannya. Tanpa webhook, penyapu /api/sync-pending (jadwalkan tiap 1-2 menit) tetap mendeteksi pembayaran.
 2. Cara uji (butuh persetujuanmu; ini transaksi nyata): beli 1 produk termurah (Rp1.000+ untuk QRIS) dengan QRIS, bayar, lalu cek:
    pesanan berubah Berhasil, saldo GVSMARTPAY TIDAK terpotong, saldo PunyaKios bertambah sebesar pembayaran dikurangi biaya.
 3. Uji "gagal": QRIS untuk nomor tujuan yang salah pada produk murah -> pesanan Gagal, saldo GVSMARTPAY bertambah.
 4. Kalau pembayaran terbaca tapi pesanan tidak terbentuk, lihat Admin > Pengaturan > Notifikasi > log pengiriman dan status
    di koleksi Firestore qrisPay (hanya server yang menulis).
DATABASE: koleksi baru qrisPay (satu dokumen per QRIS; hanya server). Pesanan QRIS memakai id yang sama dengan id QRIS dan
punya field payMethod:'qris' dan payFee. Tidak ada perubahan Firestore Rules dan tidak ada migrasi.
